# 企业财报 HTML 快照直接导入设计

## 目标

把企业财报快照的发布物从“Markdown 解析后的结构化数据”改为 Skill 生成的完整 HTML 页面。公开首页和管理端审核预览直接加载同一个 HTML 文件，不再在 `prototype.html` 中复制财务正文、表格和计算结果。

本次原型只展示已经存在 HTML 快照的公司：

- 贵州茅台，`600519.SH`，文件 `doc/价值线_贵州茅台_企业快照版.html`。
- 哔哩哔哩，`09626.HK`，文件 `doc/价值线_哔哩哔哩_企业快照版.html`。

腾讯控股和美团暂时从公开公司目录与管理列表移除，直到生成各自的企业快照 HTML。

## 范围

本次包含：

- 公开首页使用 iframe 直接加载企业快照 HTML。
- 公司目录只显示已有 HTML 快照的公司。
- 管理端从 Markdown 导入流程改成 HTML 导入流程。
- 审核页直接预览与公开端相同的 HTML。
- HTML 文件的原型校验规则、错误示例和发布阻断。
- 桌面左右结构、手机公司抽屉和管理端流程回归。

本次不包含：

- FastAPI 文件上传、数据库、目录监听或真实服务器校验。
- 在浏览器中解析财务正文、指标或表格。
- Markdown 到 HTML 的转换。
- 自动从文件系统枚举 HTML；静态原型通过内置清单登记现有文件。
- 修改 Skill 生成的贵州茅台、哔哩哔哩 HTML 或其 Markdown 源文件。
- 腾讯控股、美团或其他公司的新快照生成。

## 核心决策

采用同源 iframe 直接加载完整 HTML 文件。

选择 iframe 的原因：

- Skill 输出已经是完整、自包含的 HTML 文档。
- 财报页的 CSS、表格、锚点和响应式行为可以原样保留。
- 财报 CSS 不会污染原型首页、手机抽屉或管理端。
- 公开端和审核端可以引用同一文件路径，避免两份内容不一致。
- 未来 FastAPI 后端只需管理文件和元数据，不需要重建正文组件。

不采用 Shadow DOM 获取与注入，因为 `file://` 环境可能阻止读取文件，且需要解析和重写 `<head>`、`<style>`、`<body>` 与锚点。不采用构建时复制，因为那仍然是内容转换，而不是直接使用 HTML 发布物。

## HTML 快照清单

原型内置 `htmlSnapshots` 清单。每条记录只保存目录、审核和发布需要的元数据：

```js
{
  id: 'cn-600519-html',
  companyName: '贵州茅台',
  ticker: '600519',
  market: 'CN',
  exchange: 'SSE',
  dataAsOf: '2025-12-31',
  quoteAsOf: '2026-07-15 12:05',
  htmlPath: './价值线_贵州茅台_企业快照版.html',
  fileName: '价值线_贵州茅台_企业快照版.html',
  pageTitle: '价值线企业快照版 — 贵州茅台 (600519.SH) · 只寻找事实，不寻求意见',
  status: 'published',
  report: 'clean'
}
```

哔哩哔哩使用相同结构：

- `id`: `hk-09626-html`
- `ticker`: `09626`
- `market`: `HK`
- `exchange`: `HKEX`
- `htmlPath`: `./价值线_哔哩哔哩_企业快照版.html`
- `pageTitle`: `价值线企业快照版 — 哔哩哔哩 (09626.HK) · 只寻找事实，不寻求意见`
- `status`: `published`
- `report`: `clean`

左侧目录、右侧 iframe、管理列表和审核页都读取同一条清单记录。财务指标不进入清单，HTML 文件是财务正文和数字的唯一来源。

## 公开首页

### 公司目录

保留现有桌面左栏和手机抽屉，只显示贵州茅台与哔哩哔哩。

每张卡片显示：

- 市场。
- 数据日期。
- 公司名称。
- 证券代码与交易所。
- `HTML 快照` 文件类型标签。
- `已发布` 状态。

卡片不再显示 PE、PB、股息率和研究判词，避免在清单中复制 HTML 内的财务数据。

搜索、市场筛选、排序和默认选择行为保持不变。默认选中贵州茅台。当前公司被筛掉时，选择过滤结果中的第一家公司；没有结果时右侧不保留旧 iframe。

### 右侧阅读区

右侧保留当前公司上下文栏，显示公司名称、代码、市场和 `企业财报 HTML` 标签。上下文栏下方放置 iframe：

```html
<iframe
  class="snapshot-html-frame"
  src="./价值线_贵州茅台_企业快照版.html"
  title="贵州茅台企业财报快照"
  sandbox>
</iframe>
```

iframe 规则：

- 填满右侧剩余宽度和高度。
- iframe 文档自身承担纵向滚动。
- 不在外层再包一层正文滚动，避免双滚动条。
- 切换公司时替换 `src` 和 `title`，新文档从顶部加载。
- 使用空的 `sandbox` 属性，阻止脚本、表单提交、新窗口和外层页面操作。
- 两份现有 HTML 不含脚本或远程资源，其 CSS、表格和片段锚点可以在 iframe 内工作。

桌面端仍为 `320px + 剩余宽度`。手机端仍通过“选择公司”打开左侧抽屉；选中公司后关闭抽屉，iframe 加载相应文件。

## 管理端

### 管理列表

管理列表包含：

- 贵州茅台：已发布，校验通过。
- 哔哩哔哩：已发布，校验通过。
- HTML 格式错误示例：草稿，校验失败。

腾讯控股、美团和原 Markdown 错误示例从列表移除。

管理端文案调整：

- `上传 Markdown` → `上传 HTML`。
- `使用演示 Markdown` → `使用演示 HTML`。
- `扫描 inbox` 保留按钮名称，说明改为扫描 `.html` 文件。
- 登录页说明改为管理 HTML 导入、校验、预览和发布。

### 审核页

元数据区域显示：

- 公司名称。
- 证券代码。
- 市场。
- 数据日期。
- 行情时间。
- HTML 文件名和相对路径。
- 页面标题。
- 文件类型 `text/html`。

预览区域不再调用 `renderValueLineBody()` 或简版正文渲染器，而是使用与公开端相同的 iframe 组件和 `htmlPath`。

已发布记录保留撤回操作。校验通过的草稿可以发布。校验失败的草稿禁用发布并显示错误说明，不创建 iframe。

## HTML 校验规则

原型使用预设报告演示以下校验逻辑；未来后端按照同样规则读取文件内容。

必须通过：

1. 文件扩展名是 `.html`。
2. 包含 `<!doctype html>`。
3. 包含 `<html lang="zh-CN">` 或等价中文语言声明。
4. 包含 `<meta charset="utf-8">`。
5. 包含 viewport 元信息。
6. 包含非空 `<title>`、`<style>` 和 `<body>`。
7. 标题能够匹配清单中的公司名称与证券代码。
8. 不包含 `<script>`。
9. 不包含嵌套 `<iframe>`。
10. 不包含远程脚本、远程样式、远程图片或 CSS `@import`。

贵州茅台与哔哩哔哩的报告均为零错误、零警告。错误示例固定演示两条错误：缺少 `<title>`，并包含远程脚本。错误预览显示“HTML 校验失败，无法生成预览”，发布按钮禁用。

## 安全边界

- 公开端和审核端 iframe 均使用 `sandbox`，不添加 `allow-scripts`、`allow-forms`、`allow-popups` 或 `allow-top-navigation`。
- 原型不把 HTML 字符串插入 `innerHTML`，只设置经过清单登记的相对文件路径。
- 用户输入不能直接成为 iframe `src`。
- 只有校验通过且状态为 `published` 的记录进入公开目录。
- 文件名和页面标题在外层显示时继续使用 HTML 转义。

## 异常与空状态

- 搜索无结果：目录显示清除条件入口，右侧显示调整条件说明，不保留旧 iframe。
- 请求失败演示：目录显示重新加载，右侧隐藏 iframe。
- 快照路径缺失：审核报告显示“HTML 文件不存在”，发布按钮禁用。
- 校验失败：审核页列出具体错误，不加载 iframe。
- iframe 尚未加载：显示覆盖式 `正在加载 HTML 快照` 提示；收到 load 事件后隐藏。
- iframe 加载失败：原型显示“HTML 快照未能加载，请检查文件路径”。由于浏览器对 iframe HTTP 错误的事件支持有限，自动化测试同时检查清单中的文件实际存在。

## 移除的旧实现

完成后，以下内容不再是公开与审核预览的依赖：

- `maotai-snapshot-data` 内嵌财务 JSON。
- `renderValueLineBody()` 和相关表格生成器。
- `renderSimpleWorkspaceBody()`。
- 腾讯控股和美团的简版财务正文数据。
- 原型自行实现的最早/最近年份按钮和价值线目录。

这些交互已经包含在 Skill 输出 HTML 中或由 HTML 自身负责。若管理端其他演示代码不再引用旧函数与样式，应一并删除，避免 `prototype.html` 继续保存第二份财务内容。

## 测试与验收

自动化测试覆盖：

1. 清单只包含贵州茅台和哔哩哔哩两条公开记录。
2. 两条 `htmlPath` 对应的文件实际存在。
3. 两份 HTML 包含 doctype、title、style、body、charset 和 viewport。
4. 两份 HTML 不包含脚本、嵌套 iframe或远程资源。
5. 公开详情使用带 `sandbox` 和动态 `src` 的 iframe。
6. 左侧卡片不再复制 PE、PB、股息率和财务判词。
7. 默认选择贵州茅台，筛选与空状态规则继续有效。
8. 管理端上传、扫描、元数据和审核文案全部切换到 HTML。
9. 审核预览复用同一个 iframe 渲染器。
10. 错误示例有两条 HTML 校验错误、禁用发布且不创建 iframe。
11. 旧的内嵌财务 JSON 和正文渲染器不再存在。
12. 原型仍是不依赖远程资源的独立外壳页面。

浏览器验收覆盖：

- 桌面端切换贵州茅台与哔哩哔哩，iframe 标题、路径和可见公司内容一致。
- 两个 iframe 内的锚点和横向表格滚动可用。
- 公开外壳没有横向溢出。
- 390px 模式下抽屉可打开、关闭和切换公司。
- 管理端登录后能审核两份 HTML，并看到相同文件预览。
- 错误示例显示两条错误且不能发布。
- 公开请求失败与搜索无结果不会保留旧 iframe。
- 浏览器控制台零错误。

## 完成标准

Skill 生成的企业财报 HTML 成为唯一财务正文发布物。贵州茅台和哔哩哔哩在公开端与管理端都直接加载各自原始 HTML；原型不再维护第二份财务 JSON、表格或简版正文，并保留现有左右工作台、手机抽屉和审核发布体验。
