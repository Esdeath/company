# 文章末尾评论设计

## 目标

评论区属于每篇资料的阅读流末尾，不再与正文争抢首屏高度。读者使用页面唯一的纵向滚动浏览完整文章，滚动到正文末尾后自然进入评论区。

本次只调整公开阅读页的布局和 iframe 高度同步，不改变评论接口、审核、通知或账号行为。

## 当前问题

资料正文在固定高度 iframe 内滚动，评论由 iframe 外的父页面渲染。两者同时出现在工作台的固定视口中，导致评论压缩正文高度；父页面也无法通过空 `sandbox` 读取 iframe 的真实内容高度。

## 方案

### 统一页面滚动

`DocumentReader` 在 iframe 加载完成后读取同源文档的实际高度，并将该高度写回 iframe。正文因此不再产生独立的纵向滚动条，`CommentSection` 保持为 iframe 后面的兄弟节点。页面结构仍为：

1. 公司与资料目录
2. 完整文章正文
3. 评论与一级回复
4. 页脚

外层 `.site-shell` 使用 `min-height: 100svh`，阅读区恢复自然高度。桌面目录继续吸顶并限制在视口内；移动端目录仍使用现有抽屉。

### 高度同步

iframe 初次创建时使用稳定的视口高度，避免加载期间塌陷。加载后，`DocumentReader`：

1. 从 `documentElement` 和 `body` 的 `scrollHeight`、`offsetHeight` 中取最大值。
2. 把结果设置为 iframe 的像素高度。
3. 使用 `ResizeObserver` 监听正文根节点与 body，覆盖图片、字体和响应式排版引起的后续高度变化。
4. 切换资料、重试或卸载组件时断开观察器并取消待执行的测量，防止旧资料修改新 iframe。

测量异常或得到无效高度时保留初始阅读高度，页面仍可读取正文，不显示空白阅读器。

## 安全边界

iframe 改为 `sandbox="allow-same-origin"`，使父页面可以测量同源内容。仍不授予以下能力：

- 脚本执行
- 表单提交
- 弹窗
- 顶层或父页面导航
- 下载及其他 sandbox 权限

父页面只读取布局尺寸，不读取、复制或重写资料正文。HTML 原文件和 Markdown 生成页继续使用同一个 iframe 阅读器。

## 深链与状态

评论继续在父页面加载。通知或 URL 中的评论深链等待目标评论渲染后调用现有定位逻辑；统一页面滚动会直接将读者带到文章末尾的目标评论。

资料目录失败、正文 HEAD 探测失败和 iframe 加载失败沿用现有错误与重试状态。失败状态不挂载评论区之外的新控件。

## 验证

- 单元测试覆盖 sandbox 权限、高度测量、后续尺寸更新和切换资料后的观察器清理。
- 布局契约测试确认页面使用自然高度、iframe 使用测量高度、评论仍紧跟阅读器。
- 浏览器测试使用长文章分别验证桌面与 320px 手机视口：首屏不出现评论，滚动到正文末尾才进入评论区，无双重纵向滚动条、横向溢出或页脚遮挡。
- 更新产品、后端和开发文档中的 iframe sandbox 约定。
