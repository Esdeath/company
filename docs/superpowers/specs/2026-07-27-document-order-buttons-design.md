# 资料上下移动按钮设计

## 目标

将管理端资料目录的整行拖拽排序改为上移和下移按钮。管理员每次把一份资料移动一位，系统立即保存新顺序。公开站点继续按同一顺序展示，新上传资料继续追加到末尾。

此次改动只替换管理端排序交互。数据库 `sort_order`、完整顺序 API、上传追加规则和 Web 展示规则保持不变。

## 管理端交互

每份资料标题左侧显示两个紧凑的图标按钮：`↑` 上移一位，`↓` 下移一位。按钮使用原生 `button`，并通过 `aria-label` 标明资料名称，例如“上移 年度报告”和“下移 年度报告”。

第一项禁用上移按钮，最后一项禁用下移按钮。目录只有一项时两个按钮都禁用。按钮位置在桌面端和移动端保持一致，不放入右侧重命名操作区，避免与保存名称和删除操作混在一起。

点击有效按钮后，`DocumentList` 计算完整的新 ID 顺序并发出 `reorder` 事件。`App.vue` 沿用现有乐观更新：先显示新顺序，再调用完整顺序 API。保存成功后采用服务端响应并播报“资料顺序已保存”；失败时恢复旧顺序、显示错误并播报“已恢复原顺序”。

保存期间禁用整个资料目录的排序、重命名和删除操作。重命名或删除正在进行时也禁用排序按钮。连续点击不会产生并发排序请求。

## 移除内容

删除 `DocumentList` 中的 Pointer Events、指针捕获、拖动阈值、临时拖动状态、行中点计算和 `Alt+ArrowUp/Down` 快捷键。资料行不再获得排序专用焦点，也不再显示抓取光标、拖动透明度或插入线。

移除拖拽说明文字和相关 CSS。排序按钮保留正常键盘焦点，管理员可以用 Tab 定位按钮并按 Enter 或 Space 操作。

## 组件边界

- `DocumentList.vue` 根据当前索引渲染按钮、处理边界并发出完整 ID 顺序。
- `App.vue` 继续负责请求、乐观更新、失败恢复、竞态保护和结果播报。
- `api.ts`、FastAPI、PostgreSQL 和 Web 无需修改。

## 测试

管理端组件测试覆盖：中间项上移和下移、第一项上移禁用、最后一项下移禁用、单项目录两个按钮禁用、忙碌状态禁用、按钮发出完整 ID 顺序，以及点击重命名和删除不会触发排序。

App 测试继续覆盖保存成功、失败恢复、重复请求、公司切换竞态和资料变更期间禁用排序。删除原有指针拖动与拖动样式测试，新增按钮布局和焦点样式检查。

## 验收

- 管理员可通过上移和下移按钮把资料移动一位。
- 边界按钮正确禁用，不发送无效请求。
- 每次有效移动立即保存，失败后恢复原顺序。
- 桌面和移动端按钮不遮挡标题、输入框、保存名称或删除操作。
- 管理端刷新后顺序保持，公开站点显示相同顺序。
- 新上传资料继续出现在末尾。
- Admin 完整检查与相关工程测试通过。
