# 港股企业快照版生成器

为一只港股生成单页 HTML:`价值线_{公司简称}_企业快照版.html`,保存到用户项目根目录。
页面原则:**不寻求意见,只寻找事实**——只有实际披露数据及其直接运算,无预测、无估算、无评级、无人名、无跨公司对比。

## 流程(五步,顺序执行)

### 第 1 步:取数(两个请求并行)

用 web_fetch 并行请求(具体 URL、字段含义、返回格式见 `references/data-api.md`):

1. **年报主要财务指标**(东方财富 F10):全部年份,含上市前。
2. **实时行情**(腾讯 qt.gtimg.cn):现价、52周高低、总市值、总股本。

若某接口失败,按 references 里的备选方案重试;仍失败则告知用户缺哪块数据,不要编造。

### 第 2 步:核对数据陷阱(每次必查)

港股数据有固定的坑,逐条核对,漏一条页面就会说谎:

- **三币种混合**:财报数据是人民币,股息与股价是港元。估值折算按 1 RMB = 1.09 HKD 并在页尾注明。
- **`ISSUED_COMMON_SHARES` 是当前值**,所有历史行重复同一数字,不可当历史股本。历史加权股本 = 归母净利润 ÷ 基本EPS,逐年推算。
- **`DPS_HKD` 同样是最新值**;历史股息用各年报行的 `DPS_HKD_LY`(上一年度股息)串成序列。字段为 null = 该年未派息。
- **上市前年份失真**:可转换可赎回优先股会计会造成上市前净资产为负、巨额账面亏损、ROE/负债率无意义。每股数据表从上市年起列;经营数据表保留全部年份但对失真指标标"–"并在页尾注释说明。
- **行情可能是缓存旧价**:解析腾讯行情返回串中的时间戳,页面标题旁如实标注数据日期。
- 上市当年的加权股本受 IPO 时点影响偏低,标 `*` 并注释。

### 第 3 步:用 Python 验算所有衍生数字(禁止心算入页)

写一个脚本一次算完,页面上出现的每个衍生数字都必须出自这里:

- 入口检验:现价距 52 周低点/高点的百分比;PE-TTM、PB 与其历史值(API 的 `PE_TTM_SQ`/`PB_TTM_SQ` 可作历史参照)的相对位置
- 市值(HKD 与 RMB 双口径)、EV = 市值 − 期末现金、EV/EBIT(EBIT≈税前利润+利息;若几乎无有息负债直接用税前利润并注明)
- 经营占用资本 = 归母净资产 − 期末现金;生意回报 = EBIT ÷ 经营占用资本
- 上市后各指标 CAGR(营收、净利、经营现金流、每股口径)
- 历年加权股本、分红率 = DPS(折RMB) ÷ EPS

只做实际数据的四则运算。**不做**正常化利润、mid-cycle 假设、目标价——那些是估算,页面不收。

### 第 4 步:形成判定(先想清楚再写页面)

按固定框架给出这家公司的**具体**结论(判词要有数字证据,不写泛泛套话):

1. **入口检验**:它现在会不会出现在"新低名单"(股价新低/PE新低/PB新低)上?会→"进入渔场";不会→说明它在自身历史区间的什么位置。
2. **五步扫描**,每步给 ✓/△/✕ 和一句判词:
   - ① 长期记录:每股收益逐年序列像不像稳定上升的直线?深蹲年份是哪年、为什么?
   - ② ROE 与杠杆:ROE 高不高?对照负债率与 ROIC,判断是真回报还是杠杆水分。判词中固定点评**净现比**(经营现金流÷归母净利润,用快照现成两行相除):长期 ≥1 说明利润是真钱,长期 <1 要点名存疑——这是页面内检验"真实利润"的唯一免费手段。
   - ③ 股本变化:加权股本在缩(回购)还是在胀(增发/激励稀释)?分红趋势?
   - ④ 利润率:毛利率长期是平线(定价权)、上行线(溢价增强)还是周期函数?
   - ⑤ 估值锚:和它自己的历史比处什么位置?当前利润(分母)处在什么状态——爆发年/周期顶的低 PE 不足为凭。**若 PB 很低或接近破净(如银行、控股型公司、地产、类现金资产多的公司),不能只比历史 PE/PB,要拆资产包**:市值买到的是什么(现金、可交易证券、固定资产/地产、对外持股各值多少)、商誉占净资产多少、下行保护在哪。用快照的期末现金、总资产、归母净资产估个大致框架,细项(地产重估、持股市值)标为页面外待查。高 PB 成长股(生意值钱、资产不值钱)则跳过此步,专注盈利能力与增长质量。
3. **印章**:五步中①⑤致命伤 → 红色"翻页";入口亮灯且前两问(便宜吗?好生意吗?)未被否决 → 绿色"进入第二轮"。
4. **五问清单**:前两问在页面内作答(带证据);后三问(管理层可信吗?我漏了什么?为什么被我发现?)标"✋ 页面外",给出这家公司具体的"去处"。第 5 问点明错价理由是"无人知晓"还是"全市场分歧"。

   后三问的"去处"按**第二轮功课六类清单**展开,逐类想一遍再写,防止漏项(只写与这家公司相关的类,但六类都要想到):
   - **产品与用户**:产品实际体验、用户为什么选它、同行产品对比、差异化能否持续
   - **商业模式与行业**:竞争格局、行业数据、渠道结构——快照④只给了定价权的财务证据,竞争本身在页面外
   - **管理层言行对照**:快照③已给"做的"基线(股本、分红、配售、回购);页面外补"说的"(股东信、访谈、公开承诺),判断言行是否一致
   - **公告与财报细读**:年报分部数据、附注、费用结构、非经常项——快照是摘要,细节在原文
   - **专项验证**:针对自己不踏实的关键问题——实地考察、门店渠道观察、专业核查
   - **长期现金流判断**:未来 10–20 年现金流大致多少、机会成本对比——这是快照原则上不做的前瞻判断,必须留给使用者

### 第 5 步:渲染并交付(两个文件)

同一份判定,输出两个文件到项目根目录:

**5a. HTML** — `价值线_{公司简称}_企业快照版.html`
以 `assets/template.html` 为骨架填充(结构、CSS、模块顺序已固定,勿自创版式),替换所有 `{{...}}` 占位符。模块顺序:

头部(价格/PE/PB/股息率/市值) → 30秒结论(进入渔场 + 结论 + 五步标签) → 商业模式(含"读快照前先在脑中放一句话") → ★快照上半部(每股数据,上市后年份) → ★快照下半部(经营数据,全部年份) → 5秒心算 → 资本结构与流动性 + 年均变化率(双栏) → 五问检查清单 → 页尾(数据来源、口径注释、免责声明)。

风格红线:无人名(不写巴菲特/李录/芒格)、无维度标签、不与其他公司对比、无预测列、五问表用 `table.qa` 类保证换行。

**5b. Markdown** — `价值线_{公司简称}_企业快照版.md`
以 `assets/template.md` 为骨架填充,内容与判定和 HTML 完全一致,只是去掉 CSS 样式。用途:便于复制进雪球/公众号、纳入 git 版本管理、以及作为"决策日志"的底稿。表格用 GFM 语法;HTML 里的颜色高亮(neg/hl/印章配色)在 MD 里用**加粗**、`✕/△/✓`、或"(首次亏损)"这类文字标注替代;印章写成标题里的【进入第二轮 / 翻页】。模块顺序、页尾注释、免责声明都保留。

两个文件的数据必须一致(同一次 Python 验算的结果),不要分别生成导致数字对不上。

完成后用 present_files 同时交付两个文件,汇报一句核心画像(如"入口亮灯,生意合格,分歧在XX")。

## 判词写作要点

判词是页面的灵魂,写给"看得懂生意的人":每条判词 = 数据引用 + 商业解释 + 一个明确的 ✓/△/✕。好的判词指向下一步行动("该去年报分部数据里查什么"),坏的判词是形容词堆砌("增长强劲,前景广阔")。深蹲年份、稀释记录、利润率拐点这类"不舒服的事实"必须点名,它们比漂亮数字更有信息量。
