Vue 3 — 搭积木一样构建网页界面

本项目版本:3.5.40 · 两个前端(公开站点与管理后台)都用它

它是什么

Vue 是一个 JavaScript 界面框架:你用它把网页拆成一个个可复用的「组件」(按钮、弹窗、评论区……),并声明「数据长什么样,界面就长什么样」。数据一变,Vue 自动帮你更新页面对应的部分。

比喻:传统写网页像手工作坊 —— 每次数据变了,你要亲自找到页面上每一处受影响的地方逐个改。Vue 像一位管家:你只管把「账本」(数据)改了,管家自动把家里所有挂着这笔账的「展示牌」(页面元素)换成新数字,一处不漏。

它解决什么问题

没有框架时,前端代码要手动操作页面元素(DOM):找到元素 → 改内容 → 处理事件 → 小心别改漏。界面稍微复杂一点,这种代码就会变成难以维护的「面条」。Vue 用两件事解决它:

  • 声明式渲染:你写「界面应该是什么样」,而不是「怎么一步步改成那样」。
  • 组件化:界面拆成独立零件,每个零件自带自己的模板、逻辑、样式,可以反复使用、单独测试。

核心概念

单文件组件(.vue 文件)

一个文件三段式:<template> 写界面结构、<script> 写逻辑、<style> 写样式。一个文件就是一个积木块。

响应式数据(ref / reactive)

用 ref() 包住的数据是「被监视的」:值一变,所有用到它的界面自动重新渲染。

指令(v-if / v-for / v-on)

模板里的特殊标记:v-if 控制显示隐藏,v-for 循环渲染列表,@click 绑定点击事件。

组合式 API(Composition API)

Vue 3 的写法:把一块功能的逻辑收拢进一个函数(如 useUserSession()),多个组件可以共享复用。

感受一下一个最小的 Vue 组件:

<script setup>
import { ref } from 'vue'
const count = ref(0)          // 被监视的数据
</script>
<template>
  <button @click="count++">点了 {{ count }} 次</button>
</template>

注意你从没写过「把按钮文字改成新数字」—— 数据变了,界面自己跟上,这就是响应式。

在本项目中

位置角色
apps/web(公开站点)Vue 作为 Nuxt 框架的底座。app/components/ 里是一个个单文件组件:DocumentReader.vue(资料阅读器)、CommentSection.vue(评论区)、AuthDialog.vue(登录弹窗)等。
apps/admin(管理后台)纯 Vue 3 单页应用(SPA),用 Vite 直接驱动,没有引入路由库和状态库 —— 界面简单,手写 src/api.ts 调后端接口就够了。
apps/web/app/composables/useUserSession.ts组合式 API 的实战例子:把「当前用户登录状态」的逻辑收拢成一个可复用函数,任何组件调用它都能拿到同一份状态。

与其他技术的关系

Nuxt — 基于 Vue 的全能框架(公开站点) Vite — 开发与打包 Vue 项目的工具 TypeScript — 组件逻辑都用它写 测试 — 用 Vitest + Vue Test Utils 测组件
