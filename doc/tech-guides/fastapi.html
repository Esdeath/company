FastAPI — 后端的「点餐窗口」

本项目版本:0.139.2 · 搭配 Pydantic 2 校验数据、uvicorn 0.51 作为服务器

它是什么

FastAPI 是一个 Python Web 框架,用来编写「API 接口」:前端发来一个 HTTP 请求(比如「给我某公司的资料列表」),FastAPI 负责接住请求、调用业务逻辑、把结果打包成 JSON 返回。它有两位固定搭档:Pydantic 负责校验进出的数据格式,uvicorn 是实际监听端口、承接网络连接的服务器程序。

比喻:后端像一家只做外卖的餐厅。uvicorn 是店门口的取餐窗口(网络监听),FastAPI 是前台点单员 —— 看单号(URL 路径)决定转给哪个档口(路由函数),Pydantic 是那位较真的收单员 —— 订单格式不对(缺字段、类型错)当场退回,不让厨房浪费工夫做错菜。

它解决什么问题

  • 裸写 HTTP 处理太苦:解析请求、校验参数、序列化响应、生成文档,框架全部代劳,你只写业务逻辑。
  • 接口文档过期:FastAPI 根据代码自动生成 OpenAPI 文档(访问 /docs 有可交互界面)。本项目把这份 OpenAPI 当作前后端的「合同」—— 前端照它写类型,永不脱节。
  • 高并发等待:基于 Python 的 async(异步)能力,等数据库、等磁盘的时间可以去处理别的请求,不傻等。

核心概念

路由(Route)

「URL + HTTP 方法 → 处理函数」的对应表:GET /api/companies 由某个函数处理,POST 由另一个。

Pydantic 模型

用类声明数据形状,进来的请求自动校验、出去的响应自动序列化 —— 相当于后端版的 TypeScript 接口。

依赖注入(Depends)

处理函数声明「我需要数据库会话 / 当前登录用户」,框架自动准备好递进来,方便替换和测试。

应用工厂(create_app)

用一个函数组装出整个应用(注册路由、连数据库),测试时可以随时「再造一个隔离的应用实例」。

@router.get("/companies/{company_id}/documents")
async def list_documents(company_id: UUID) -> list[DocumentOut]:
    """URL 里的 company_id 自动解析成 UUID,格式错直接 422。
    返回值按 DocumentOut 模型自动转成 JSON。"""
    return await service.list_documents(company_id)

在本项目中

后端代码在 apps/api/src/company_api/,采用清晰的三层分工(「点单 → 配菜 → 库房」):

文件角色
main.pycreate_app 工厂:组装依赖、注册路由。uvicorn 用 --factory 模式启动它。
routes.py资料主线的所有接口定义(点单层):公司增删改查、资料上传/浏览。
library_service.py业务编排(配菜层):上传时按扩展名分流、调渲染、写索引写文件;单个文件失败只回滚该文件,不拖累同批次。
repository.py / content_store.py存取层(库房):前者读写 PostgreSQL 索引,后者读写文件系统正文。
auth_routes.py → auth.py → auth_repository.py认证一条线:登录、会话、CSRF 校验(详见安全篇)。
schemas.py / config.pyPydantic 模型定义;pydantic-settings 从环境变量读配置(如 CONTENT_ROOT、DATABASE_URL)。

与其他技术的关系

Python — FastAPI 的编写语言 SQLAlchemy — repository 层用它访问数据库 Markdown 渲染 — 上传管线的核心一环 安全认证 — auth 三件套详解 Nginx — /api/ 前缀的流量都转给它
