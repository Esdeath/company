Node.js 与 pnpm — 前端世界的地基和仓库管理员

本项目版本:Node 24.18.0(.nvmrc 锁定)· pnpm 10.34.5(经 corepack)

它们是什么

Node.js 让 JavaScript 离开浏览器也能运行 —— 在你的电脑上、在服务器上。前端的一切工具(Vite、Nuxt、测试、检查)都是跑在 Node 上的 JS 程序;本项目上线后的 web 服务本身也是一个 Node 进程。

pnpm 是「包管理器」:前端项目会依赖成百上千个别人写好的代码包,pnpm 负责按清单下载、安装、管理它们。它比老牌的 npm 更快、更省磁盘(相同的包全机只存一份,用硬链接复用)。

比喻:Node 是「发电站」—— 没有它,所有前端电器(工具链)都没法通电运转。pnpm 是「中央仓库管理员」—— 项目需要的每个零件(依赖包)都登记在清单(package.json)上,管理员按清单精确进货;而且全城只建一个仓库,各项目要用就拉根专线过去,不重复囤货。

它们解决什么问题

  • 「在我电脑上能跑」综合征:每个人 Node 版本不同、装的包版本不同,程序行为就可能不同。本项目用 .nvmrc 锁 Node 版本、用 lockfile 锁每个包的精确版本,人人环境一致。
  • 依赖地狱:上千个包的版本关系靠人管必乱。lockfile(pnpm-lock.yaml)像一张精确到小数点的进货清单,任何机器照单安装,结果完全一样。
  • 多项目共存:本仓库有 web、admin 两个前端,pnpm 的 workspace(工作区)让它们住在同一仓库里、共享一次安装。

核心概念

package.json

项目的「身份证 + 依赖清单」:名字、脚本命令、依赖哪些包及版本范围。

lockfile(pnpm-lock.yaml)

把「版本范围」钉死成「精确版本」的快照。装包时加 --frozen-lockfile 表示:严格照快照装,对不上就报错,绝不自作主张。

workspace 工作区

pnpm-workspace.yaml 声明仓库里有哪些子项目(本项目:apps/web、apps/admin),可用 --filter 只对某个子项目执行命令。

corepack

Node 自带的「包管理器的管理器」:读取 package.json 里的 packageManager: pnpm@10.34.5,自动用这个精确版本的 pnpm,版本也不会漂。

在本项目中

位置角色
.nvmrc锁定 Node 24.18.0,make setup 会先校验版本。
根 package.jsonpackageManager: pnpm@10.34.5 + engines.node: >=24.18.0 <25,双保险锁版本。
pnpm-workspace.yaml显式列出 apps/web 与 apps/admin(scaffold 测试禁止用通配符,必须点名)。
日常命令一律 corepack pnpm ...,例如 corepack pnpm --filter @company/web check 只检查 web 端。
纪律lockfile 与声明不一致时,不要用非 frozen 安装绕过 —— 应重新生成 lockfile 并连同声明文件一起提交。这是 CLAUDE.md 写明的项目铁律。
