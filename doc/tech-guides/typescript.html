TypeScript — 给 JavaScript 加一层「安检」

本项目版本:5.9.3 · 两个前端全部代码都用它编写,并开启最严格模式

它是什么

TypeScript(简称 TS)是 JavaScript 的超集:在 JS 的基础上增加了「类型标注」。你可以声明一个变量是数字、一个函数必须返回字符串、一个对象必须有哪些字段 —— 写错了,编辑器立刻画红线,根本等不到运行。浏览器不认识 TS,所以它最终会被编译成普通 JS 再运行。

比喻:JavaScript 像不核对取件码的快递柜 —— 什么包裹都能塞进去,拿错了也要等拆开才发现。TypeScript 像加了核对的快递柜:存件时登记「这一格只放文件袋」,有人想塞进一箱苹果,当场拒收,而不是等收件人拆开才傻眼。

它解决什么问题

JavaScript 太宽容了:变量可以随时变类型、访问不存在的字段也不报错、拼错名字只有运行到那一行才炸。小脚本无所谓,但项目一大,这类低级错误会源源不断。TS 把这些错误的发现时机从「用户用的时候」提前到「你写代码的时候」,同时让编辑器拥有精准的自动补全 —— 因为它知道每个对象上有什么。

核心概念

类型标注

let n: number = 1 —— 冒号后面写类型。给 n 赋字符串会立刻报错。

接口 / 类型别名

interface Company { id: string; name: string } —— 描述一个对象的「形状」,少字段、错字段都逃不过检查。

类型推断

不是处处都要手写类型:const x = 42,TS 自动推断 x 是数字。标注只写在关键边界(函数参数、接口数据)。

strict 严格模式

一组最严格的检查开关,比如「可能为空的值必须先判空才能用」。本项目两个前端都开着它。

interface Document {
  id: string
  title: string
  publishedAt: string | null   // 明确告诉所有人:可能没有发布时间
}
function show(doc: Document) {
  doc.publishedAt.slice(0, 10)  // ❌ 编译不过:它可能是 null!
  if (doc.publishedAt) {
    doc.publishedAt.slice(0, 10) // ✅ 判空之后才允许用
  }
}

在本项目中

位置角色
apps/web/nuxt.config.ts配置 typescript: { strict: true, typeCheck: true },开发时就实时做类型检查。
apps/admin全部 .ts / .vue 代码用 TS 编写,vue-tsc(3.3.7)负责检查 .vue 文件里的类型。
make check 的前端部分两个前端的 check 都包含 typecheck 步骤:类型不过关,整个质量检查就不过关。
前后端契约后端 FastAPI 自动生成 OpenAPI 接口文档,前端据此定义 TS 类型 —— 接口改了、前端没跟上,类型检查会先叫起来。

与其他技术的关系

Vue — 组件逻辑用 TS 编写 Node.js — TS 编译与检查工具跑在 Node 上 FastAPI — OpenAPI 契约是前端类型的来源 测试质量 — typecheck 是 make check 的一环
