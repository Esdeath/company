Nginx — 站在大门口的前台接待

本项目版本:1.30.4(edge 容器)· 配置在 infra/nginx/default.conf

它是什么

Nginx(读作 engine-x)是一个高性能 Web 服务器 / 反向代理。本项目主要用它的「反向代理」能力:所有浏览器请求先到 Nginx,它看一眼网址前缀,把请求转发给真正干活的后端服务,再把响应带回给浏览器。

比喻:公司大楼只有一个前台。访客(浏览器请求)一律先到前台报来意,前台看一眼事由(URL 前缀):谈业务的领去业务部(web)、来办内部事务的领去行政部(admin)、送文件的领去收发室(api)。访客从头到尾不知道各部门在几楼、有几个工位 —— 这就是「反向」代理:代理的是服务器那一侧,对外只露一张脸。

它解决什么问题

  • 一个域名,多个服务:web、admin、api 是三个独立进程,但用户只应看到一个网址。Nginx 按路径分发,三合一。
  • 安全收口:后端服务全部藏在内网,只有 Nginx 对外开门 —— 攻击面从五个变一个。
  • 统一处理公共事务:HTTPS 加密、转发真实 IP、限流,都在门口一次做完。

核心概念

location 匹配

配置文件里一段段 location /api/ { ... }:按 URL 前缀决定这类请求怎么处理。

proxy_pass 转发

把请求原样转给上游服务。细节魔鬼:目标地址带不带尾斜杠,决定转发时是否剥掉匹配前缀(见下)。

转发头(X-Forwarded-*)

转发时附上真实来源信息(访客 IP、原始协议),否则后端只能看到「请求全来自 Nginx」。

健康检查端点

直接在 Nginx 层响应 /healthz,探活请求不打扰后端、不写访问日志。

在本项目中

infra/nginx/default.conf 是 edge 容器的全部配置,三条转发规则:

规则说明
/admin/ → http://admin:8080/目标带尾斜杠 ⇒ 转发时剥掉 /admin 前缀。admin 容器里的静态服务器以为自己就在根路径,而浏览器端资源地址靠 Vite 的 base: '/admin/' 补齐 —— 两处配置一唱一和。另有 = /admin 精确匹配,308 重定向到 /admin/。
/api/ → http://api:8000目标不带尾斜杠 ⇒ 保留 /api 前缀原样转发,FastAPI 的路由本身就以 /api 开头。
/ → http://web:3000兜底:其余全部流量给 Nuxt 公开站点。

此外统一注入 Host / X-Real-IP / X-Forwarded-For / X-Forwarded-Proto 四个转发头。生产环境还有第二层 Nginx:装在宿主机上,负责 HTTPS 和公网入口,把流量转给容器里的这个 edge(详见部署篇)。

与其他技术的关系

Vite — base '/admin/' 与尾斜杠规则呼应 Nuxt — / 兜底流量的接收者 FastAPI — /api/ 流量的接收者 部署 — 宿主机上还有一层 HTTPS Nginx Docker — edge 是五服务之一
