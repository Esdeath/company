Make 与工程约定 — 项目的「总开关面板」

入口:根目录 Makefile · 一条命令干一件事

它是什么

Make 是一个诞生于 1976 年、至今坚挺的老牌构建工具。本项目用它做「命令门面」:把各种啰嗦的多步操作(装依赖、起服务、跑检查、部署)封装成一个个简短的 make xxx 命令,写在根目录的 Makefile 里。

比喻:Makefile 像家里的智能开关面板:「观影模式」一个按钮背后是关窗帘、调灯光、开音响一串动作。你不需要记住每个设备的遥控器怎么用(pnpm 的参数、uv 的参数、docker compose 的参数),按面板上的按钮就行。新人进项目,看一眼面板就知道这个家怎么运转。

它解决什么问题

  • 命令太长记不住:docker compose --env-file .env up -d postgres vs make dev-infra,高下立判。
  • 步骤有先后依赖:比如启动 API 前必须先跑数据库迁移,Make 的依赖机制自动保证顺序。
  • 人人做法一致:所有人都走同一组命令,不会出现「我是这样启动的」的流派之争。

本项目的开关面板

命令作用
make setup校验 node/pnpm/uv/docker 版本,然后 frozen 安装前后端全部依赖。新人第一步。
make dev-infra只启动 PostgreSQL 容器(混合开发的地基)。
make dev并行起 web/admin/api 三个开发服务器(改代码即时生效)。
make db-upgrade数据库迁移到最新结构(alembic upgrade head)。
make check全量质量检查:契约测试 + 两个前端 lint/typecheck/test/build + 后端 ruff/mypy/pytest。提交前必跑。
make compose-up / compose-smoke / compose-down整套 Docker 启动 / 端到端冒烟 / 停止。
make deploy-aliyun部署到阿里云 ECS,日常更新一条命令。

两种开发模式

  • 混合开发(日常):数据库在容器里(make dev-infra),三个应用直接跑在本机(make dev)—— 热更新快、调试方便。注意先把 .env 里 DATABASE_URL 的主机从 postgres 改成 127.0.0.1。开发地址:Web :3000、Admin :5173/admin/、API :8000。
  • 完整 Compose(仿真产线):五个服务全进容器,入口 127.0.0.1:8080 —— 和生产环境同构,用于最终验证。

硬性纪律(CLAUDE.md 钦定)

  • 依赖全部走 frozen lockfile:锁文件对不上,不许用非 frozen 安装绕过,要重新生成并连声明文件一起提交。
  • Python 一律 uv run,pnpm 一律 corepack pnpm —— 保证用的永远是锁定版本的工具。
  • 版本三件套:.nvmrc(Node 24.18.0)、.python-version(3.13)、packageManager(pnpm 10.34.5),并被 scaffold 测试守护。

与其他技术的关系

pnpm — make 背后的前端包管理 uv — make 背后的 Python 管理 Docker — compose 系列命令的实体 测试质量 — make check 的全部内容 部署 — make deploy-aliyun
