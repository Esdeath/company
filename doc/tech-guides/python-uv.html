Python 与 uv — 后端的语言和它的高速管家

本项目版本:Python 3.13(.python-version 锁定)· uv 0.11.29

它们是什么

Python 是本项目后端使用的编程语言,以「像读英语一样好懂」著称,是数据、AI、Web 后端领域的主流语言之一。本项目的 API 服务(接收请求、渲染 Markdown、读写数据库)全部用 Python 编写。

uv 是新一代 Python 包管理与项目工具(用 Rust 编写,速度飞快),对 Python 的作用相当于 pnpm 对 Node:装依赖、锁版本、管理虚拟环境、运行命令,一个工具全包。

比喻:如果说前端(JavaScript/Node)是「店面装修队」,Python 就是「后厨团队」的工作语言 —— 顾客看不到,但每道菜(每个接口响应)都出自它手。uv 则是后厨的采购主管:菜谱(pyproject.toml)上写着要哪些原料,它按锁定的供货单(uv.lock)精确进货,每个项目还有独立的储藏间(虚拟环境),互不串味。

它们解决什么问题

  • 为什么后端用 Python? 生态成熟(Web 框架、数据库驱动、Markdown 渲染都有现成高质量库)、代码可读性强、开发效率高。
  • Python 环境之乱:一台电脑上多个 Python 版本、包装到系统里互相冲突,是老大难。uv 用「每个项目一个虚拟环境 + lockfile 锁版本」根治,替代了过去 pip/venv/poetry 等一堆工具的组合。

核心概念

pyproject.toml

Python 项目的「身份证 + 依赖清单」,对应前端的 package.json。本项目在 apps/api/pyproject.toml。

虚拟环境(venv)

项目专属的隔离 Python 环境,依赖装在项目自己的 .venv 里,不污染系统。uv 自动创建管理。

uv sync --frozen

按 uv.lock 精确安装依赖,锁文件对不上就报错 —— 和前端 frozen lockfile 同一纪律。

uv run

「在项目虚拟环境里执行命令」:uv run pytest、uv run alembic upgrade head,不用手动激活环境。

在本项目中

位置角色
apps/api/整个后端是一个 uv 管理的 Python 3.13 项目,包名 company_api,源码在 src/company_api/。
.python-version锁定 Python 3.13,pyproject 里声明 >=3.13,<3.14。
依赖清单FastAPI、SQLAlchemy、Alembic、markdown-it-py、pwdlib[argon2] 等全部精确锁版本(后续各篇分别介绍)。
日常命令项目铁律:Python 一律经 uv run 执行 —— uv run pytest、uv run ruff check .、uv run mypy src。
容器构建API 的 Dockerfile 基于 python:3.13-slim + uv,构建时同样 frozen 安装,保证线上线下一致。

与其他技术的关系

FastAPI — 用 Python 写的 Web 框架 SQLAlchemy — 用 Python 对象读写数据库 Node/pnpm — 前端世界的对应角色 测试质量 — pytest/ruff/mypy 都经 uv run
