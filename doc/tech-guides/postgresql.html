PostgreSQL — 项目的「档案总馆」

本项目版本:18.4(容器镜像 postgres:18.4-alpine)

它是什么

PostgreSQL(常叫 Postgres)是世界上最受欢迎的开源关系型数据库:数据按「表」存放,表有固定的列,行与行之间可以建立关联;它保证数据的一致性和持久性 —— 断电、崩溃都不丢已确认的数据。

比喻:数据库像图书馆的档案总馆。每类档案一个柜子(表),每份档案格式统一(列),柜子之间有交叉引用(外键:某份资料档案上写着「属于 3 号公司」)。馆里还有一位一丝不苟的管理员(事务机制):要么一整套手续办完,要么全部作废重来,绝不出现「借书证注销了一半」的状态。

它解决什么问题

  • 数据不能靠文件乱放:多个请求同时读写、按条件查询、保证唯一性(公司代号不能重复)—— 这些文件系统做不了,数据库天生擅长。
  • 崩溃安全:写入先记日志再落盘,机器宕机也能恢复到一致状态。
  • 约束即防线:唯一约束、检查约束写在表结构里,脏数据在门口就被拦下,不依赖应用代码自觉。

核心概念

表 / 行 / 列

表 = 一类东西(companies);行 = 一条记录(某家公司);列 = 一项属性(名称、代号)。

SQL

操作数据库的通用语言:SELECT ... FROM ... WHERE ...。本项目由 SQLAlchemy 代写,人基本不手写。

事务(Transaction)

一组操作要么全部成功要么全部撤销 —— 「转账扣了钱但没到账」这种半截状态不可能出现。

索引与约束

索引让按条件查找飞快;唯一/外键/检查约束让非法数据根本进不来。

在本项目中

方面说明
存什么公司表、资料索引表、管理员会话表、用户与评论表。特意不存资料正文 —— 正文是几十上百 KB 的 HTML,放文件系统(CONTENT_ROOT)更合适,数据库只记「哪家公司有哪份资料、文件放哪」。这叫「索引入库、正文落盘」。
怎么跑Compose 里的 postgres 服务,数据存在 postgres_data 卷里,容器重建数据不丢。
网络隔离只绑定 127.0.0.1:5432(外网连不上),且只挂在 backend 内部网络 —— 五个服务里只有 api 能碰到数据库,web/admin 想连都没有路。
结构演进表结构由 Alembic 迁移脚本管理,见 apps/api/migrations/versions/。
备份生产环境有 systemd 定时器(company-backup.timer)定期备份数据库与内容目录。
