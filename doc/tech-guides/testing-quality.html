测试与代码质量 — 全天候值班的质检团队

pytest 9 · Vitest 4 · Node 内置 test runner · ruff · mypy(strict) · ESLint

它们是什么

自动化测试是一批「检查代码的代码」:预先写好「输入什么、应该得到什么」,一条命令全部跑一遍,改坏了立刻报警。静态检查则不运行代码,直接扫描源码找问题:风格混乱、可疑写法、类型对不上。两者合起来构成项目的质量防线,总开关是 make check。

比喻:没有测试的项目像没有质检的工厂 —— 每次改流水线,只能靠老师傅肉眼把关,漏一个次品就流向客户。自动化测试是安检门 + 全套质检流水线:每件出厂品(每次改动)自动过一遍全部检测仪;静态检查则像投产前的图纸审查 —— 尺寸标错了,根本不用等开机就打回。

核心概念

单元测试

针对一个函数/组件的小测试:「给渲染函数一段 Markdown,应输出这样的 HTML」。快、多、密。

断言(assert)

测试的核心动作:「断言结果等于预期」。不等 = 测试失败 = 有人改坏了东西。

Lint(风格与坏味道检查)

扫出未使用的变量、危险写法、不统一的格式。ruff(Python)和 ESLint(JS/TS)各管一边。

类型检查

mypy(Python)与 vue-tsc(TS)核对所有类型标注 —— 本项目 mypy 开 strict 最严模式。

冒烟测试(smoke test)

整套系统起起来,走一遍最关键的主流程(能访问、能上传、能阅读),确认「没冒烟没起火」。

契约测试

本项目特色:根目录测试锁定工程约定本身 —— 文件必须存在、配置必须一致、文档不许出现废弃说法。脚手架被误改,测试先叫。

在本项目中 — make check 的完整清单

防线工具与位置
工程契约Node 内置 test runner(零依赖)跑 tests/docs.test.mjs、tests/prototype.test.mjs、tests/scaffold.test.mjs —— 守护文档措辞、原型清单、脚手架一致性。
前端 × 2corepack pnpm --filter @company/web check(admin 同理)= ESLint + typecheck + Vitest(配 @vue/test-utils + happy-dom 模拟浏览器)+ 生产构建。
后端风格uv run ruff check . + uv run ruff format --check .(规则集 E/F/I/UP/B/SIM)。
后端类型uv run mypy src,strict 模式。
后端行为uv run pytest,配 httpx 直接对 FastAPI 应用发起测试请求,不用真起服务器。
端到端make compose-smoke:整套容器起好后,脚本模拟真实用户走完「登录 → 上传 → 浏览」主流程。

单独跑某一项也容易,比如 uv run pytest tests/test_routes.py::test_某用例 只跑一个用例 —— 修 bug 时反馈秒回。
