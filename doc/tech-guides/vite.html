Vite — 前端的开发服务器与打包机

本项目版本:8.1.5 · 驱动管理后台(admin),也是 Nuxt 的底层引擎

它是什么

Vite(法语「快」,读作 /vit/)是一个 前端构建工具,干两件事:开发时提供一个「改代码立刻见效果」的本地服务器;上线前把几十上百个源码文件打包压缩成浏览器高效加载的少量静态文件。

比喻:写前端像做菜。开发阶段,Vite 是「明档厨房」—— 你改一勺调料,试吃窗口立刻端出新口味(热更新),不用整桌菜重做;上线阶段,Vite 是「中央厨房打包线」—— 把所有半成品统一处理、去掉厨余(没用到的代码)、封装成标准料理包(压缩后的 JS/CSS 文件),送到哪里都能直接加热上桌。

它解决什么问题

  • 开发慢:老一代工具(如 Webpack)每次启动都要把整个项目打包一遍,大项目启动要几十秒。Vite 利用浏览器原生模块能力,启动几乎瞬时,改动只热替换那一个模块。
  • 浏览器不认识源码:.vue 文件、TypeScript 浏览器都无法直接运行,Vite 负责即时把它们翻译成浏览器能懂的 JS。
  • 上线体积:生产构建时做打包、压缩、按需拆分,让用户下载得又少又快。

核心概念

开发服务器(dev server)

vite dev 起一个本地网站,源码按需即时编译,配合 HMR(热模块替换)保存即刷新。

生产构建(build)

vite build 输出 dist/ 目录:一堆压缩好的 HTML/JS/CSS 静态文件,交给任意 Web 服务器托管。

插件

Vite 本身很小,靠插件支持各种文件类型 —— 本项目用 @vitejs/plugin-vue 让它认识 .vue 单文件组件。

base 路径

告诉打包产物「你将来会被挂在网站哪个子路径下」,资源引用才能生成正确的地址。

在本项目中

位置角色
apps/admin/vite.config.ts管理后台直接由 Vite 驱动,配置了 base: '/admin/' —— 因为上线后整个后台挂在 /admin/ 子路径下(由 Nginx 转发),打包产物里的资源地址必须带这个前缀。这一条还被根目录 scaffold 测试锁定,防止误改。
admin 的 Dockerfile构建阶段跑 vite build,把产出的静态文件塞进一个 Nginx 小镜像 —— 上线的 admin 容器里只有静态文件,没有 Node。
apps/web(间接)Nuxt 底层同样用 Vite 做开发服务器与构建,所以 web 端也享受同样的秒级热更新。
测试Vitest(名字就来自 Vite)复用同一套编译管线跑单元测试,配置零重复。

与其他技术的关系

Vue — Vite 负责编译 .vue 文件 Nuxt — 底层构建引擎就是 Vite Nginx — /admin/ 前缀转发与 base 配置呼应 Docker — build 产物被装进 Nginx 镜像
