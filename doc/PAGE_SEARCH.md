# 搜索页设计

## 页面目标

搜索页处理公司名称、证券代码和市场筛选。首版不搜索 Markdown 全文，不提供复杂财务条件筛选。

## 路由和状态

路由为 `/search`，查询条件全部写入 URL：

```text
/search?q=腾讯&market=HK&sort=data_desc&cursor=...
```

支持的参数：

| 参数 | 值 | 默认值 |
|---|---|---|
| `q` | 公司名称或证券代码 | 空 |
| `market` | `CN`、`HK` | 全部 |
| `sort` | `data_desc`、`published_desc`、`name_asc` | `data_desc` |
| `cursor` | API 返回的游标 | 空 |

刷新、复制链接和浏览器前进后退都应恢复相同结果。

## 页面布局

## 搜索规则

- 去除关键词首尾空格。
- 证券代码按市场标准化后精确匹配优先。
- 公司简称和全称使用不区分大小写的包含匹配。
- `00700`、`700` 在港股搜索中都能命中 `00700`。
- A 股代码保持六位，例如 `600519`。
- 空关键词允许按市场浏览全部公司。
- 关键词最长 80 个字符，超出时前端阻止提交，API 返回 `422`。

## 结果排序

默认排序：

1. 证券代码精确匹配。
2. 公司名称精确匹配。
3. 公司名称前缀匹配。
4. 其他名称包含匹配。
5. 相同相关度按数据日期降序。

用户选择其他排序后，不再混用相关度顺序。

## 分页

- API 使用游标分页，每页 24 条。
- 页面使用“上一页、下一页”，不展示不可跳转的伪页码。
- 切换关键词、市场或排序时清空游标。
- 返回列表后恢复滚动位置。

## 响应式规则

- 手机端搜索框和按钮同排，筛选与排序分两行。
- 桌面端搜索、市场和排序放在同一工具栏。
- 结果卡片与首页共用 `SnapshotCard`。
- 手机端不使用抽屉筛选，首版条件少，直接展示更清楚。

## 键盘操作

- `/` 聚焦搜索框，但输入框已聚焦时不拦截。
- `Enter` 提交搜索。
- `Escape` 清空输入框内容，不自动发请求。
- 所有筛选和分页按钮可通过 Tab 操作。

## 分析事件

首版只记录匿名聚合事件，不记录 IP 对应的个人搜索历史：

- `search_submitted`
- `market_filter_changed`
- `search_result_opened`

如果不接入分析服务，可以先保留事件接口，不阻塞 MVP。
