# 后端设计

## 职责与边界

本文定义资料直传的目标接口；当前 `doc/prototype.html` 没有真实后端。FastAPI 负责接收 HTML 和 Markdown、保存文件、生成 Markdown 展示页、维护公司与资料索引，并提供公开读取。

HTML 和 Markdown Skill 输出是可信管理员输入。服务不检查正文、远程资源、脚本、业务元数据或重复内容，只按扩展名分流，并处理读取、渲染、写入和数据库错误。

除 `/api/health/live` 与 `/api/health/ready` 外，所有业务 API 都使用 `/api/v1` 前缀。JSON 字段使用 `snake_case`，时间使用带时区的 ISO 8601；列表使用游标分页。OpenAPI 是前后端接口契约来源。这两个基础设施端点是唯一不版本化例外，不要求管理员认证，只返回最小状态且不泄露内部信息：`live` 只表示 FastAPI 进程存活，`ready` 只返回能否接收请求的布尔状态。

直传写入接口在本切片中不要求认证，只能在本地开发与验收环境启用。它不具备生产写入授权；生产环境必须在后续工作中加入管理员认证、授权和 CSRF 防护后才能开放。

## 公司与资料索引

公司记录至少包含 `id`、名称、市场和证券代码。资料索引包含 `id`、`company_id`、`title`、`format`、`source_path`、`rendered_path`、`original_filename` 和 `uploaded_at`。路径使用系统生成的 ID；同名文件可以建立多条资料记录。

数据库保存公司和资料索引，不保存文件正文。公开列表按公司返回资料摘要；公开详情返回资料标题、格式和内容 URL，不返回服务器绝对路径。

## 文件存储与内容响应

文件存放在 `content/companies/<company-id>/<document-id>/`：

```text
source.html
source.md
rendered.html
```

- HTML 保存为 `source.html`，内容响应直接返回该文件。
- Markdown 保存为 `source.md`，上传时生成 `rendered.html`，内容响应返回生成文件。
- 数据库保存公司和资料索引，不保存文件正文。
- 系统只按扩展名分流，并处理读取、渲染、写入和数据库错误。
- 批量上传按文件提交；一个文件失败不撤销同批次中已完成的文件。

HTML 内容保持上传字节。Markdown 使用 `doc/templates/markdown/template.html` 和内联样式生成展示页；模板升级后，后台可以从 `source.md` 批量重新生成 `rendered.html`，不改动源文件。

## 上传与失败处理

管理端先选择或新建公司，再提交一个或多个 `.html`、`.md` 文件。服务从 HTML `<title>` 或 Markdown 第一个一级标题取得展示标题；缺失时使用文件名。

每个文件先写入临时位置。服务完成 Markdown 渲染和索引写入后才移动到最终目录。读取、渲染、写入或数据库操作失败时，服务删除该文件的临时数据并返回该文件的错误；其他文件继续独立处理。服务拒绝不支持的扩展名。

## API 形状

公开端读取公司目录、公司资料列表和单份资料内容。内容响应根据资料格式返回 `source.html` 或 `rendered.html`。

本地直传接口接收公司标识和多个文件，并对每个文件返回 `id`、`title`、`format`、内容 URL 或错误。实现时避免把原始文件名当作路径；服务生成目录 ID 并阻止路径穿越。

## 公开阅读

公开目录列出已建立索引的资料内容。HTML 原文件与 Markdown 生成页都可被同一个 iframe 阅读器加载；iframe 保留空 `sandbox`。服务不根据内容决定资料是否显示。

## 测试

单元测试覆盖 HTML 标题、Markdown 一级标题和文件名回退，以及扩展名分流和模板渲染。集成测试覆盖单文件临时数据清理、源文件与展示页写入、索引写入和批量逐文件结果。接口测试还覆盖基础设施健康端点和对服务器路径的隔离。
