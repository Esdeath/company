# 产品与界面设计

## 当前范围

`doc/prototype.html` 是交互参考。当前已经实现管理员登录与退出、公司选择、HTML 与 Markdown 多文件上传、逐文件最终结果、公开资料列表和阅读器。未登录时管理端只显示登录表单，不请求公司或资料数据。

## 公开工作区

桌面端依次显示公司目录、当前公司的资料列表和阅读区。用户选择公司后浏览该公司的资料列表，再打开一份资料。资料写入索引后立即可见；空资料库与空公司分别显示可读的空状态。公司或资料目录请求失败时显示对应的重试操作，不显示服务端堆栈。

iframe 自动匹配渲染后文章的完整高度，完整正文、评论区和页脚依次进入同一个页面滚动流。评论由 Nuxt 父页面渲染，不进入 iframe，也不修改上传资料。访客可读已发布评论；登录用户可发布顶层评论或一级回复、编辑和删除自己的评论、举报他人评论，并从通知定位到相关讨论。320px 宽度下编辑器与回复操作不产生页面横向滚动。

新用户的首次评论显示待审核状态，仅本人和管理员可见；管理员批准该评论后，用户后续评论直接公开。账户页支持修改用户名、密码和回复邮件偏好，并明确账户删除会撤销会话、删除私有资料且把保留评论匿名化。`USER_REGISTRATION_ENABLED=false` 时显示“注册暂未开放”；`COMMENT_WRITES_ENABLED=false` 时保留评论读取并显示“评论区暂时只读”。评论、通知或邮件失败不影响公司目录和资料阅读。

## 公司选择与上传

管理员先选择既有公司或新建公司，然后通过多文件选择器选择一个或多个 `.html`、`.md` 文件。上传前列出所选文件名；提交时显示整批上传状态，完成后显示逐文件最终结果。

每个成功结果显示资料标题。每个失败结果显示该文件的可读错误，并保留其他文件的成功结果。上传完成后，当前公司的资料列表立即刷新；资料标题可重命名，资料也可删除。管理端不提供绕过隔离阅读器的内容直链。

## 统一阅读器

HTML 原文件与 Markdown 生成页都由同一个 iframe 阅读器加载。阅读器先用 HEAD 请求确认内容端点可用，再创建带可读 `title`、仅允许同源测量的 `sandbox` iframe：

```html
<iframe sandbox="allow-same-origin"></iframe>
```

`allow-same-origin` 只供 Nuxt 父页面读取同源正文的渲染尺寸并让 iframe 自动匹配文章高度，不允许执行脚本，也不允许表单、下载、弹窗、导航或任何其他权限；父页面不读取或改写正文。内容探测与页面加载期间显示进度提示；探测或加载失败时显示只重试当前内容的操作，资料目录失败则使用独立的目录重试。系统把 HTML 和 Markdown 当作可信管理员输入，但 iframe 继续承担阅读隔离。

## 移动端公司抽屉

移动端隐藏桌面公司栏，以“选择公司”按钮打开移动端公司抽屉。抽屉使用 `role="dialog"` 和 `aria-modal="true"`，打开后把焦点移到关闭按钮，并把 Tab 与 Shift+Tab 锁定在抽屉内。用户可用关闭按钮、遮罩或 Escape 关闭；关闭或选择公司后，焦点返回“选择公司”按钮。抽屉打开时锁定页面滚动。

抽屉内显示公司目录；选择公司后关闭抽屉并回到资料列表与阅读区。移动端不依赖横向滚动完成选择公司或打开资料。

## 状态与错误处理

- 上传中：显示整批上传状态并暂时锁定公司选择和重复提交。
- 单文件错误：显示该文件的读取、渲染、写入、数据库或扩展名错误；同批次其他文件继续显示自己的结果。
- 资料列表为空：显示当前公司的空状态和公司选择入口。
- 阅读错误：保留资料列表，区分目录重试与当前内容重试。
- 状态播报：使用 `aria-live="polite"` 汇报上传最终结果和加载状态。

## 安全边界

所有阅读入口使用仅允许同源测量的 `sandbox` iframe，除 `allow-same-origin` 外不授予其他权限。界面不显示绝对文件路径、异常堆栈、Cookie、密钥或内部追踪信息。登录页使用浏览器密码管理器可识别的 `autocomplete` 属性；前端只把服务器返回的 CSRF 令牌保存在内存中，认证 Cookie 由浏览器以 `HttpOnly` 方式管理。会话失效后，界面清空管理数据并返回登录页。

## 可访问性

上传控件必须可由键盘操作，并把文件格式、进度和逐文件结果交给读屏器。阅读器提供清楚的 `title`。公司列表、资料列表和抽屉内的焦点顺序与视觉顺序一致。
