# 产品与界面设计

## 当前范围

`doc/prototype.html` 是交互参考。资料直传切片提供公司选择、HTML 与 Markdown 多文件上传、逐文件结果、公开资料列表和阅读器。写入在本轮只限本地开发与验收，界面不应把它描述为可用于生产的管理入口。

## 公开工作区

桌面端左侧显示公司目录，右侧显示当前公司资料。用户选择公司后浏览该公司的资料列表，再打开一份资料。资料写入索引后立即可见；空公司显示资料为空的状态和选择其他公司的入口。

目录支持公司名称、证券代码和市场筛选。筛选变化后保留仍在结果中的当前公司，否则选择第一项；没有结果时提供清除筛选操作。网络请求失败时保留筛选条件并显示重试操作，不显示服务端堆栈。

## 公司选择与上传

管理员先选择既有公司或新建公司，然后在同一个操作中选择多个 `.html`、`.md` 文件，或把文件拖入上传区。上传区显示文件名、格式、进度和逐文件结果。

每个成功结果显示资料标题和打开阅读器的操作。每个失败结果显示该文件的可读错误，并保留其他文件的成功结果。上传完成后，当前公司的资料列表立即刷新。

## 统一阅读器

HTML 原文件与 Markdown 生成页都由同一个 iframe 阅读器加载。阅读器创建带可读 `title` 的 iframe，并保持空权限的 `sandbox`：

```html
<iframe sandbox></iframe>
```

不要增加 `allow-scripts`、`allow-same-origin`、表单、弹窗或导航权限。加载期间显示进度提示；加载失败时显示重试与返回资料列表的操作。系统把 HTML 和 Markdown 当作可信管理员输入，但 iframe 继续承担阅读隔离。

## 移动端公司抽屉

移动端隐藏桌面公司栏，以“选择公司”按钮打开移动端公司抽屉。抽屉使用 `role="dialog"` 和 `aria-modal="true"`，打开后把焦点移到关闭按钮，并把 Tab 与 Shift+Tab 锁定在抽屉内。用户可用关闭按钮、遮罩或 Escape 关闭；关闭或选择公司后，焦点返回“选择公司”按钮。抽屉打开时锁定页面滚动。

公司目录、筛选、资料列表和阅读入口在抽屉内保持可用。移动端不依赖横向滚动完成选公司、筛选或打开资料。

## 状态与错误处理

- 上传中：逐文件显示进度，允许用户等待全部结果。
- 单文件错误：显示该文件的读取、渲染、写入、数据库或扩展名错误；同批次其他文件继续显示自己的结果。
- 资料列表为空：显示当前公司的空状态和公司选择入口。
- 阅读错误：保留资料列表，显示重试与返回操作。
- toast：使用 `aria-live="polite"` 汇报上传与重试结果。

## 安全边界

所有阅读入口使用空 `sandbox` iframe。界面不显示绝对文件路径、异常堆栈、Session、密钥或内部追踪信息。直传界面只可在本地开发与验收环境使用；生产写入入口要等管理员认证、授权和 CSRF 防护完成后再设计。

## 可访问性

上传控件必须可由键盘操作，并把文件格式、进度和逐文件结果交给读屏器。阅读器提供清楚的 `title`。公司列表、资料列表和抽屉内的焦点顺序与视觉顺序一致。
